在 Electron 中，GET 請求通常用於以下情境：

  1. TSSO 登入首頁 / OAuth 授權：開啟登入頁面（如 https://tsso.com/oauth/authorize?client_id=xxx）。
  2. 獲取使用者資料 / 設定檔：向伺服器查詢個人資訊、權限清單、系統公告。
  3. 檢查版本更新：向伺服器查詢是否有新版 .exe。

1. GET 請求與 POST 請求在攔截時的差異

POST 請求的命令與資料通常放在 Payload (Body) 中，而 GET 請求沒有 Body，所有命令與參數都會直接帶在 URL 網址後方的 Query String（即 ? 後面的鍵值對）。

先前提供的 Hook 程式碼中的 webRequest.onBeforeSendHeaders 已經將所有請求方法（包含 GET、POST、PUT、DELETE）一網打盡。

攔截到 GET 請求時的 Log 日誌範例：

[TARGET_URL]:
"https://tsso.company.com/oauth/v2/authorize?response_type=code&client_id=desktop_app&redirect_uri=app%3A%2F%2Fcallback&state=xyz123"

"GET"

2. 針對 Node.js 原生 https 的雙重防護（100% 盲點覆蓋）

Electron 的 session.defaultSession.webRequest 可以攔截 90% 以上 的網路請求（包含 WebView、BrowserWindow、fetch、XHR 以及 Electron 的 net.request）。

但如果開發者在 main.js 裡使用了 Node.js 原生的 require('https') 或 axios（預設走 Node http 模組）發送 GET 請求，Chromium 的 webRequest 偶爾會漏掉。

為了確保 100% 完全攔截，建議在 main.js 頂部加入 Node.js 原生 HTTP/HTTPS Hook：

/**
 * 補強：Hook Node.js 原生 http/https 模組 (防止 main.js 繞過 Chromium 網絡層)
 */
const http = require('http');
const https = require('https');

[http, https].forEach((module) => {
  const origRequest = module.request;
  module.request = function (...args) {
    let options = args[0];
    if (typeof options === 'string') {
      options = new URL(options);
    }
    
    const method = options.method || 'GET';
    const host = options.host || options.hostname;
    const path = options.path || '/';
    const fullUrl = `${options.protocol || 'https:'}//${host}${path}`;

    // 只印出非靜態檔案的 GET/POST 請求
    if (!fullUrl.match(/\.(png|jpg|css|js|woff2)(\?.*)?$/i)) {
      console.log(`\n[Node.js 原生 ${method} 請求防漏捕捉] -> ${fullUrl}`);
    }

    return origRequest.apply(this, args);
  };
});

3. GET 請求攔截後，Python 該如何處理與填入？

當你在 Log 中看到 METHOD: "GET" 時，Python 處理起來比 POST 更簡單，因為不需要構建 JSON Body，直接使用 requests.get() 即可。

範例：從 Log 還原 GET 請求

假設 Log 攔截到的 GET 網址為：
https://api.company.com/v1/user/info?user_id=8888&token=abc123xyz

Python 填入寫法：

import requests

session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Electron/28.0.0"
})

# 方式 1：直接填入完整帶有 Query 的網址發送 GET
get_url = "https://api.company.com/v1/user/info?user_id=8888&token=abc123xyz"
response = session.get(get_url)

print(f"GET 回應狀態碼: {response.status_code}")
print(f"GET 回應內容: {response.json()}")


# 方式 2：把 URL 與 Query 參數拆開 (維護性更高，推薦)
base_url = "https://api.company.com/v1/user/info"
query_params = {
    "user_id": "8888",
    "token": "abc123xyz"
}

response = session.get(base_url, params=query_params)
print(f"解析後的結果: {response.json()}")

總結

  1. GET 請求絕對攔得下來，資料會出現在 TARGET_URL 的 ? 後面。
  2. 在 Python 中，把 ? 後面的參數轉成字典檔（Dictionary），帶入 requests.get(url, params=params) 即可完全還原 Electron main.js 的 GET 動作。

進行全方位架構審查後，發現過去單純攔截 session.webRequest 與 ipcMain 時存在 5 個關鍵技術盲點。以下先進行盲點剖析與補強說明，接著提供 100% 完整的 main.js Hook 程式碼與對應的 Python 自動化腳本。

關鍵盲點與補強剖析

  1. Node.js 原生網路繞過 (Node.js Network Bypass)：
    • 問題：Electron 主進程（Main Process）可直接呼叫 Node.js 原生的 http.request、https.request 或 Node 18+ 的 globalThis.fetch。這些請求走的是 Node.js 的 C++ 網路層，完全不會經過 Chromium 的 session.webRequest。
    • 補強：在 main.js 頂層重寫 http.request、https.request 及 globalThis.fetch。
  2. 動態視窗與 WebContents 漏抓：
    • 問題：若應用程式透過 iFrame、WebWorker 或動態彈出新視窗（如 TSSO 登入彈窗），單靠 app.on('browser-window-created') 會漏掉非視窗型的 webContents。
    • 補強：改用全域 app.on('web-contents-created') 綁定所有渲染進程。
  3. 二進位與非 UTF-8 數據毀損 (Binary / Protobuf / MessagePack)：
    • 問題：若 API 使用 Protobuf、MessagePack 或加密 Byte 陣列傳輸，直接 .toString('utf8') 會導致字元亂碼或截斷，使 Python 無法還原 Payload。
    • 補強：加入自動二進位檢測，無法轉為 UTF-8 時自動降級轉換為 Hex 或 Base64 編碼輸出。
  4. 對稱加密與 PKCE 隨機碼捕捉：
    • 問題：現代 OAuth/TSSO 常搭配 PKCE (code_verifier) 或 AES 前端加密。若僅攔截 HMAC，會無法取得 AES 的 IV 與 Key。
    • 補強：加鉤 crypto.createCipheriv / crypto.createDecipheriv 與 crypto.pbkdf2 / crypto.randomBytes。
  5. 自訂 Protocol Scheme (如 myapp://) 攔截：
    • 問題：當 TSSO 完成驗證並呼叫自訂協定時，Windows 下可能經由命令列參數 process.argv 或 second-instance 傳遞。
    • 補強：強化 second-instance 與 open-url 的參數解析邏輯。

一、完整 HOOK MAIN.JS 程式碼

請將以下程式碼直接貼在 Electron main.js 檔案的最頂端（位於任何 require 之前）：

/**
 * =========================================================================
 * Electron 全管道無盲點逆向分析注入器 (Full-Coverage Hook)
 * 涵蓋：Chromium WebRequest, Node.js HTTP/HTTPS/Fetch, WebContents/IPC,
 *       Crypto (HMAC/AES/PKCE), SafeStorage, Protocol Deep-Link
 * =========================================================================
 */
(function __ELECTRON_FULL_COVERAGE_HOOK__() {
  const HOOK_FLAG = Symbol.for('__REVERSE_HOOKED_FLAG__');
  if (global[HOOK_FLAG]) return;
  global[HOOK_FLAG] = true;

  const fs = require('fs');
  const path = require('path');
  const http = require('http');
  const https = require('https');
  const crypto = require('crypto');
  const { app, session, ipcMain, safeStorage } = require('electron');

  // 1. 日誌與遞增序號管理
  let stepCounter = 1;
  const getStepId = () => `#${String(stepCounter++).padStart(6, '0')}`;
  const dateStr = new Date().toISOString().split('T')[0];
  const LOG_PATH = path.join('D:\\', `electron_captured_data_${dateStr}.txt`);

  function safeSerialize(val, maxLen = 10000) {
    const cache = new Set();
    try {
      if (Buffer.isBuffer(val)) {
        const isUtf8 = !val.some(b => (b < 32 && b !== 9 && b !== 10 && b !== 13) || b === 127);
        return isUtf8 
          ? val.toString('utf8') 
          : `[Buffer (Hex)]: ${val.toString('hex')}\n[Buffer (Base64)]: ${val.toString('base64')}`;
      }
      const str = JSON.stringify(val, (key, value) => {
        if (typeof value === 'object' && value !== null) {
          if (cache.has(value)) return '[Circular]';
          cache.add(value);
        }
        if (typeof value === 'bigint') return value.toString();
        if (Buffer.isBuffer(value)) return `<Buffer len=${value.length}>`;
        return value;
      }, 2);
      return (str && str.length > maxLen) ? str.substring(0, maxLen) + '\n...[內容過長已截斷]' : (str || 'undefined');
    } catch (e) {
      return `[無法序列化: ${e.message}]`;
    }
  }

  function writeLog(category, title, fields = {}) {
    const stepId = getStepId();
    const timestamp = new Date().toISOString();
    let body = '';
    for (const [k, v] of Object.entries(fields)) {
      body += `[${k}]:\n${typeof v === 'object' ? safeSerialize(v) : v}\n\n`;
    }
    const content = `==================== [ ${stepId} | ${category} | ${title} | ${timestamp} ] ====================\n${body}================================================================================\n\n`;
    console.log(content);
    try {
      fs.appendFileSync(LOG_PATH, content, 'utf8');
    } catch (e) {
      const fallback = path.join(app.getPath('temp'), `electron_analysis_${dateStr}.txt`);
      fs.appendFileSync(fallback, content, 'utf8');
    }
  }

  writeLog('SYSTEM', '主進程啟動參數', { 'CMD_LINE': process.argv, 'PID': process.pid });

  // 2. Hook Node.js 原生 HTTP / HTTPS 模組 (防止繞過 Chromium Session)
  [http, https].forEach((mod) => {
    const origReq = mod.request;
    mod.request = function (...args) {
      let options = args[0];
      if (typeof options === 'string') {
        try { options = new URL(options); } catch (e) {}
      } else if (options instanceof URL) {
        options = {
          protocol: options.protocol,
          hostname: options.hostname,
          port: options.port,
          path: options.pathname + options.search,
          method: 'GET'
        };
      }
      
      const method = (options && options.method) || 'GET';
      const host = (options && (options.host || options.hostname)) || 'localhost';
      const pathStr = (options && (options.path || options.pathname)) || '/';
      const fullUrl = `${(options && options.protocol) || 'http:'}//${host}${pathStr}`;

      if (!fullUrl.match(/\.(png|jpg|css|js|woff2|ico)(\?.*)?$/i)) {
        writeLog('NODE-NET-OUT', `[Node.js 原生] ${method} -> ${fullUrl}`, {
          'URL': fullUrl,
          'METHOD': method,
          'HEADERS': options.headers || {}
        });
      }
      return origReq.apply(this, args);
    };
  });

  // 3. Hook Node 18+ 全域 Fetch
  if (globalThis.fetch) {
    const origFetch = globalThis.fetch;
    globalThis.fetch = async function (input, init = {}) {
      const url = typeof input === 'string' ? input : (input.url || input);
      const method = init.method || 'GET';
      writeLog('NODE-FETCH-OUT', `[Fetch API] ${method} -> ${url}`, {
        'URL': url,
        'METHOD': method,
        'HEADERS': init.headers || {},
        'BODY': init.body || '無'
      });
      return origFetch.apply(this, arguments);
    };
  }

  // 4. Hook Chromium Session (網絡層全捕捉: 入站/出站/302重導向/Cookie)
  function attachSessionHooks(targetSession, sessionTag = 'Default') {
    if (!targetSession || targetSession[HOOK_FLAG]) return;
    targetSession[HOOK_FLAG] = true;

    const filter = { urls: ['<all_urls>'] };

    // 出站 (Send Request)
    targetSession.webRequest.onBeforeSendHeaders(filter, (details, callback) => {
      const { url, method, requestHeaders } = details;
      if (!url.match(/\.(png|jpg|jpeg|gif|css|js|woff2|ico)(\?.*)?$/i)) {
        let payload = '無';
        if (details.uploadData && details.uploadData.length > 0) {
          const buffers = details.uploadData.map(d => d.bytes).filter(Boolean);
          if (buffers.length > 0) payload = safeSerialize(Buffer.concat(buffers));
        }
        writeLog('CHROMIUM-NET-OUT', `[Chromium] ${method} -> ${url}`, {
          'SESSION': sessionTag,
          'URL': url,
          'METHOD': method,
          'HEADERS': requestHeaders,
          'PAYLOAD': payload
        });
      }
      callback({ requestHeaders });
    });

    // 302 重導向 (TSSO 回傳 Code 攔截核心)
    targetSession.webRequest.onBeforeRedirect(filter, (details) => {
      writeLog('TSSO-REDIRECT', `302 重導向命令`, {
        'SESSION': sessionTag,
        'FROM_URL': details.url,
        'REDIRECT_TO_URL': details.redirectURL,
        'STATUS_CODE': details.statusCode
      });
    });

    // 入站 (Response)
    targetSession.webRequest.onHeadersReceived(filter, (details, callback) => {
      const { url, statusCode, responseHeaders } = details;
      if (!url.match(/\.(png|jpg|jpeg|gif|css|js|woff2|ico)(\?.*)?$/i)) {
        writeLog('CHROMIUM-NET-IN', `[Chromium] 回應 <- ${url}`, {
          'SESSION': sessionTag,
          'URL': url,
          'STATUS_CODE': statusCode,
          'HEADERS': responseHeaders
        });
      }
      callback({ cancel: false, responseHeaders });
    });

    targetSession.cookies.on('changed', (event, cookie, cause, removed) => {
      if (!removed) {
        writeLog('COOKIE', 'Cookie 寫入/更新', {
          'DOMAIN': cookie.domain,
          'NAME': cookie.name,
          'VALUE': cookie.value
        });
      }
    });
  }

  app.whenReady().then(() => {
    attachSessionHooks(session.defaultSession, 'Default');
    const origFromPartition = session.fromPartition;
    session.fromPartition = function (partition, options) {
      const sess = origFromPartition.call(this, partition, options);
      attachSessionHooks(sess, `Partition: ${partition}`);
      return sess;
    };
  });

  // 5. Hook Deep-Link Protocol (外部喚醒命令)
  app.on('second-instance', (event, commandLine) => {
    writeLog('DEEP-LINK', '多重執行個體喚醒命令 (Second Instance)', { 'COMMAND_LINE': commandLine });
  });

  app.on('open-url', (event, url) => {
    event.preventDefault();
    writeLog('DEEP-LINK', 'macOS/Protocol 喚醒 URL', { 'URL': url });
  });

  // 6. Hook IPC 與 WebContents (渲染層與主進程雙向命令)
  const origHandle = ipcMain.handle;
  ipcMain.handle = function (channel, listener) {
    return origHandle.call(this, channel, async (event, ...args) => {
      writeLog('IPC-HANDLE-REQ', `UI -> 主進程 [Invoke]: "${channel}"`, { 'ARGS': args });
      try {
        const res = await listener(event, ...args);
        writeLog('IPC-HANDLE-RES', `主進程 -> UI [Result]: "${channel}"`, { 'RESULT': res });
        return res;
      } catch (err) {
        writeLog('IPC-HANDLE-ERR', `IPC 執行異常: "${channel}"`, { 'ERROR': err.message });
        throw err;
      }
    });
  };

  const origOn = ipcMain.on;
  ipcMain.on = function (channel, listener) {
    return origOn.call(this, channel, (event, ...args) => {
      writeLog('IPC-ON-REQ', `UI -> 主進程 [Send]: "${channel}"`, { 'ARGS': args });
      return listener(event, ...args);
    });
  };

  app.on('web-contents-created', (event, contents) => {
    const origSend = contents.send;
    contents.send = function (channel, ...args) {
      if (!contents.isDestroyed()) {
        writeLog('IPC-MAIN-PUSH', `主進程 -> UI [Push]: "${channel}"`, { 'TARGET_ID': contents.id, 'ARGS': args });
      }
      return origSend.apply(this, [channel, ...args]);
    };
  });

  // 7. Hook 加密模組 (HMAC, AES, safeStorage, PKCE)
  app.whenReady().then(() => {
    if (safeStorage && safeStorage.isEncryptionAvailable()) {
      if (safeStorage.decryptString) {
        const origDecrypt = safeStorage.decryptString;
        safeStorage.decryptString = function (buf) {
          const res = origDecrypt.call(this, buf);
          writeLog('SAFE-STORAGE', '本地 safeStorage 解密內容', { 'DECRYPTED_TEXT': res });
          return res;
        };
      }
    }
  });

  // HMAC 簽名 Hook
  const origCreateHmac = crypto.createHmac;
  crypto.createHmac = function (algorithm, key) {
    const hmac = origCreateHmac.call(this, algorithm, key);
    const origUpdate = hmac.update;
    const keyStr = safeSerialize(key);
    hmac.update = function (data) {
      writeLog('CRYPTO-HMAC', 'HMAC 簽名計算', {
        'ALGORITHM': algorithm,
        'KEY': keyStr,
        'DATA': safeSerialize(data)
      });
      return origUpdate.apply(this, arguments);
    };
    return hmac;
  };

  // AES 對稱加密 Hook
  const origCreateCipheriv = crypto.createCipheriv;
  crypto.createCipheriv = function (algorithm, key, iv) {
    writeLog('CRYPTO-AES-ENCRYPT', 'AES 加密初始化', {
      'ALGORITHM': algorithm,
      'KEY': safeSerialize(key),
      'IV': safeSerialize(iv)
    });
    return origCreateCipheriv.call(this, algorithm, key, iv);
  };

  const origCreateDecipheriv = crypto.createDecipheriv;
  crypto.createDecipheriv = function (algorithm, key, iv) {
    writeLog('CRYPTO-AES-DECRYPT', 'AES 解密初始化', {
      'ALGORITHM': algorithm,
      'KEY': safeSerialize(key),
      'IV': safeSerialize(iv)
    });
    return origCreateDecipheriv.call(this, algorithm, key, iv);
  };
})();

二、完整 Python 自動化腳本

這份 Python 腳本涵蓋 GET Query 解析、POST (Form/JSON) 自動發送、302 Redirect 授權碼 (code) 擷取、動態 HMAC 簽名算法還原以及 Token 自動帶入機制：

import requests
import hmac
import hashlib
import time
import json
import base64
from urllib.parse import urlparse, parse_qs

# =========================================================================
# 【參數設定區】：請根據 main.js 印出的 D:\electron_captured_data_YYYY-MM-DD.txt 填入
# =========================================================================

# 1.1 從 [CHROMIUM-NET-OUT] 或 [NODE-NET-OUT] 的 URL 填入
TSSO_LOGIN_URL = "https://tsso.company.com/api/v1/login"          # TSSO 登入驗證 URL
TOKEN_EXCHANGE_URL = "https://chat.company.com/api/v1/oauth/token" # Code 換取 Token 的 URL
API_BASE_URL = "https://chat.company.com/api/v1"                   # 業務命令 API 基礎 URL

# 1.2 從 [CHROMIUM-NET-OUT] 的 PAYLOAD / HEADERS 填入
CLIENT_ID = "desktop_chat_app"
DEFAULT_USER_AGENT = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Electron/28.0.0"

# 1.3 從 [CRYPTO-HMAC] 的 KEY 與 ALGORITHM 填入
HMAC_SECRET_KEY = "secret_key_from_log_123"
HMAC_ALGORITHM = "sha256"


class ElectronAutomationClient:
    def __init__(self):
        # 建立 Session，保持 Cookie 續航與全局 Header 狀態
        self.session = requests.Session()
        self.session.headers.update({
            "User-Agent": DEFAULT_USER_AGENT,
            "Accept": "application/json, text/plain, */*",
            "Content-Type": "application/json;charset=UTF-8"
        })
        self.access_token = None
        self.refresh_token = None

    # =========================================================================
    # 邏輯 1：HMAC 動態簽名算號器 (還原 [CRYPTO-HMAC] 標籤中的 DATA 拼接邏輯)
    # =========================================================================
    def _generate_hmac(self, method: str, path: str, timestamp: str, body_str: str = "") -> str:
        """
        對照 [CRYPTO-HMAC] Log 中 DATA 的樣式調整拼接格式：
        例如：POST/api/v1/message/send1724925600{"text":"hello"}
        """
        raw_data = f"{method.upper()}{path}{timestamp}{body_str}"
        
        signature = hmac.new(
            key=HMAC_SECRET_KEY.encode('utf-8'),
            msg=raw_data.encode('utf-8'),
            digestmod=hashlib.sha256
        ).hexdigest()
        
        return signature

    # =========================================================================
    # 邏輯 2：發送 GET 請求範例 (對照 [CHROMIUM-NET-OUT] METHOD: "GET")
    # =========================================================================
    def fetch_system_config(self):
        print("\n[GET 請求] 正在取得系統初始化設定檔...")
        url = f"{API_BASE_URL}/system/config"
        params = {
            "client_id": CLIENT_ID,
            "version": "1.0.0",
            "ts": str(int(time.time()))
        }
        
        response = self.session.get(url, params=params)
        print(f"-> 回應狀態碼: {response.status_code}")
        print(f"-> 回應內容: {response.json()}")
        return response.json()

    # =========================================================================
    # 邏輯 3：TSSO 登入與攔截 302 重導向 (對照 [TSSO-REDIRECT])
    # =========================================================================
    def login_tsso(self, username, password):
        print("\n[TSSO 登入] 正在送出帳戶憑證...")
        
        payload = {
            "username": username,
            "password": password,
            "client_id": CLIENT_ID,
            "response_type": "code",
            "redirect_uri": "mychat://auth/callback"
        }

        # 關鍵點：設定 allow_redirects=False，才能擷取 302 重導向標頭中的 Location
        response = self.session.post(
            TSSO_LOGIN_URL,
            data=payload, # 若 Log 顯示 Content-Type 為 json，改用 json=payload
            allow_redirects=False
        )

        print(f"-> 登入請求狀態碼: {response.status_code}")

        # 攔截 [TSSO-REDIRECT] REDIRECT_TO_URL
        if response.status_code in [301, 302]:
            redirect_url = response.headers.get("Location")
            print(f"-> [攔截成功] 收到 302 重導向指令: {redirect_url}")
            
            # 從 Protocol URL 中解析出 Code 參數
            parsed = urlparse(redirect_url)
            query_params = parse_qs(parsed.query)
            
            if 'code' in query_params:
                auth_code = query_params['code'][0]
                print(f"-> [解析成功] 取得 Authorization Code: {auth_code}")
                return self.exchange_access_token(auth_code)
            else:
                raise ValueError("重導向網址中未包含 code 參數！")
        else:
            # 部分系統會在 200 OK 的 JSON 中直接回傳 code
            res_data = response.json()
            if "code" in res_data:
                return self.exchange_access_token(res_data["code"])
            raise Exception(f"TSSO 登入失敗: {response.text}")

    # =========================================================================
    # 邏輯 4：用 Code 換取 Access Token (對照 [CHROMIUM-NET-IN] 與 [IPC-MAIN-PUSH])
    # =========================================================================
    def exchange_access_token(self, auth_code):
        print("\n[Token 交換] 正在使用 Auth Code 換取 JWT Access Token...")
        
        payload = {
            "grant_type": "authorization_code",
            "code": auth_code,
            "client_id": CLIENT_ID
        }

        response = self.session.post(TOKEN_EXCHANGE_URL, json=payload)
        res_data = response.json()

        if response.status_code == 200 and "access_token" in res_data:
            self.access_token = res_data["access_token"]
            self.refresh_token = res_data.get("refresh_token")
            
            # 將 Token 自動加入後續所有請求的 Header 中
            self.session.headers.update({
                "Authorization": f"Bearer {self.access_token}"
            })
            print(f"-> [成功] 已取得 Access Token: {self.access_token[:25]}...")
            return True
        else:
            raise Exception(f"Token 交換失敗: {response.text}")

    # =========================================================================
    # 邏輯 5：發送簽名業務命令 (對照 [IPC-HANDLE-REQ] -> [CRYPTO-HMAC] -> [CHROMIUM-NET-OUT])
    # =========================================================================
    def send_business_command(self, action_name: str, payload_data: dict):
        print(f"\n[業務命令] 發送命令: [{action_name}]...")
        
        if not self.access_token:
            raise Exception("尚未取得 Authorization Token，請先進行登入！")

        target_path = "/api/v1/command/execute"
        full_url = f"{API_BASE_URL}/command/execute"
        timestamp = str(int(time.time()))

        body_dict = {
            "action": action_name,
            "data": payload_data
        }
        # 緊湊 JSON 序列化（消除多餘空格，確保與 JS JSON.stringify 格式完全一致）
        body_str = json.dumps(body_dict, separators=(',', ':'))

        # 計算簽名
        signature = self._generate_hmac("POST", target_path, timestamp, body_str)

        # 帶入動態簽名標頭
        headers = {
            "X-Timestamp": timestamp,
            "X-Signature": signature,
            "Content-Type": "application/json"
        }

        response = self.session.post(full_url, data=body_str, headers=headers)
        print(f"-> 執行結果狀態碼: {response.status_code}")
        
        try:
            result = response.json()
            print(f"-> 接收回傳資料:\n{json.dumps(result, indent=2, ensure_ascii=False)}")
            return result
        except Exception:
            print(f"-> 接收原始內容: {response.text}")
            return response.text

3. 操作注意事項與調試技巧

  1. JSON 格式化一致性 (separators=(',', ':'))：
    • JavaScript 的 JSON.stringify() 預設在冒號與逗號後不加空格（如 {"a":1,"b":2}）。
    • Python 的 json.dumps() 預設會加上空格（如 {"a": 1, "b": 2}）。
    • 解決方案：Python 中傳送 JSON 字串或計算 HMAC 時，必須加上 separators=(',', ':')，否則會因為空格差異導致 HMAC 簽名驗證失敗。
  2. 302 重導向與 Session Cookie (allow_redirects=False)：
    • 發送 TSSO 登入請求時，必須在 session.post() 設定 allow_redirects=False。
    • 這是因為 302 轉址鏈中攜帶了關鍵的 Location 標頭與 Cookie。若讓 Python 自動重導向，將無法捕捉到中間的 code 參數。
  3. 二進位資料處理 (Protobuf / MessagePack)：
    • 若日在 Log 中看到 [Buffer (Hex)] 或 [Buffer (Base64)]，表示該介面使用非文字格式傳輸。
    • 在 Python 中需改用 bytes.fromhex("...") 或 base64.b64decode("...") 處理 Body。

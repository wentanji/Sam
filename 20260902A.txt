除了 PyInstaller，將 Python 程式打包或轉譯成 Windows .exe 可執行檔還有以下幾種主要方式：

1. Nuitka（效能最佳與原始碼保護）

原理：將 Python 程式碼翻譯成 C/C++ 程式碼，再調用 C 編譯器（如 GCC 或 MSVC）編譯成原生 .exe。

優點：執行速度通常比一般打包工具更快，且因為轉為 C 程式碼，具備極高的程式碼防護能力，能有效防止反編譯。

適用情境：對執行效能有要求、或希望保護商業邏輯原始碼不被竊取的專案。

2. cx_Freeze（跨平台且穩定）

原理：與 PyInstaller 類似，將 Python 解譯器、依賴庫與腳本打包在一起。

優點：支援 Windows、macOS 與 Linux，透過 setup.py 腳本設定，靈活性極高且長期維護良好。

適用情境：需要跨平台打包或偏好透過程式碼精細控制打包過程的專案。

3. PyOxidizer（基於 Rust 的新世代打包工具）

原理：將 Python 解譯器嵌入到 Rust 產生的單一可執行檔中，可直接在記憶體中載入模組。

優點：啟動速度極快，單一檔案打包的完整度高，且不需要在硬碟中解壓暫存檔。

缺點：設定較複雜，學習曲線比 PyInstaller 陡峭。

4. py2exe（Windows 專用老牌工具）

原理：專為 Windows 設計的打包工具，能將 Python 腳本轉為 Windows .exe 與服務（Windows Service）。

優點：針對 Windows 環境優化，設定直覺。

適用情境：僅針對 Windows 平台開發的小型或傳統專案。

5. 免安裝 Python（Python Embedded Package）+ 啟動外殼（免編譯方案）

原理：下載 Python 官方提供的嵌入版免安裝包（Python Embedded Zip），將程式碼與依賴套件放入同一個資料夾，並透過編寫一個 .bat 啟動檔，或使用 Bat to Exe Converter 包裝成 .exe。

優點：完全不需要經歷 Python 代碼打包過程，能 100% 避免防毒軟體對打包工具（如 PyInstaller）的誤報（False Positive）。

適用情境：經常遭遇防毒軟體攔截或需要完全自主掌控運行環境的情境。

如果你的核心需求是防止他人反編譯、查看或修改原始碼，最有效的解決方案如下：

1. 使用 Nuitka（最推薦：直接編譯為 C/C++ 機器碼）
Nuitka 不是「打包」Python，而是將 Python 程式碼翻譯成真正的 C/C++ 原始碼，再調用 MSVC 或 GCC 等編譯器將其編譯成原生機器碼 (.exe)。

優點：程式碼安全性高、執行效能提升、操作相對簡單。

常用指令：

Bash
pip install nuitka
nuitka --standalone --onefile --enable-plugin=tk-inter main.py
2. 使用 PyArmor（專業級代碼混淆與加密）
PyArmor 是專門針對 Python 程式碼保護設計的混淆工具，它不只做簡單的變數重命名，而是會對位元組碼進行動態加密、控制流混淆以及加入反偵錯（Anti-debugging）機制。

防護原理：將 Python 函式體加密，只有在執行到該函式時才會在記憶體中動態解密，執行完畢立即重新加密。即使被抽取出 .pyc 也無法還原出邏輯。

搭配打包：可以先用 PyArmor 混淆加密程式碼，再調用打包工具生成 .exe：

Bash
pip install pyarmor
pyarmor gen --pack pyinstaller main.py
優點：具備高強度的程式碼保護，甚至支援設定「試用期限」或「綁定特定電腦硬體序號」。

3. 將核心邏輯改用 Cython 編譯為 .pyd 檔
如果不想整個專案重構，可以將最關鍵、最核心的商業邏輯模組（例如 core.py）獨立出來。

防護原理：利用 Cython 將 core.py 編譯成 Windows 的 C 擴充動態連結庫（.pyd），這也是編譯成機器碼的形式。

架構方式：

將核心演算法寫在 core.py，用 Cython 編譯產生 core.pyd。

主程式 main.py 直接 import core 調用。

最後用 PyInstaller 等工具打包 main.py 與 core.pyd。他人即使解包 .exe，也只能拿到編譯後的二進位 core.pyd。

如果環境只能使用 Python 工具（意即透過 pip 安裝，且無法或不便安裝 Visual Studio、GCC 等外部 C/C++ 編譯器），PyArmor 與 AST 程式碼混淆工具 是最佳解決方案。

1. PyArmor + PyInstaller（推薦：高強度加密，僅需 pip 安裝）

PyArmor 雖然底層具備強大的動態加密機制，但它本身封裝為標準 Python 套件，完全不需要你在系統中預先安裝任何 C/C++ 編譯器。

安裝方式：

Bash
pip install pyarmor pyinstaller
運作機制：PyArmor 會加密 Python 位元組碼（Bytecode）並加入控制流混淆。打包後，他人即便使用反編譯工具抽取內容，也只能拿到無法讀取的加密區塊。

操作步驟：

對程式碼進行加密混淆：

Bash
pyarmor gen -O dist_protected main.py
使用 PyInstaller 將加密後的檔案打包成獨立 .exe：

Bash
pyarmor gen --pack pyinstaller main.py
2. AST 程式碼混淆（python-minifier）+ 打包（100% 純 Python 邏輯）

如果環境要求必須是 100% 純 Python 代碼操作，可以在打包前透過 AST（抽象語法樹）解析器將原始碼「混淆與極小化」。

安裝方式：

Bash
pip install python-minifier pyinstaller
運作機制：將程式碼中的變數名、函式名、類別名全部替換成無意義的亂碼（如 _0x1a2b），並移除所有註解、字串文檔與換行。

防護效果：即便對手使用 pycdc 或 uncompyle6 將 .exe 反編譯還原成 Python 程式碼，獲得的也會是一團極度混亂、無法閱讀且難以修改的「亂碼程式」，動一字就會導致程式崩潰。

指令範例：

Bash
# 將 main.py 混淆並輸出為 main_obf.py
pyminify main.py --rename-globals --rename-locals --remove-literal-statements > main_obf.py

# 再將混淆後的檔案打包成 exe
pyinstaller --onefile main_obf.py
3. 使用 Python 內建 compileall 編譯為 .pyc（免安裝任何額外套件）

如果不允許安裝任何第三方混淆工具，可以使用 Python 官方標準庫：

操作步驟：

使用內建模組將 .py 編譯為位元組碼 .pyc：

Bash
python -m compileall main.py
將生成在 __pycache__/ 資料夾下的 .pyc 檔案檔名改回 main.pyc。

直接拿 main.pyc 來作為進入點進行 PyInstaller 打包，並將原有的 .py 原始碼刪除。

備註：單純 .pyc 仍有被反編譯的風險，建議先搭配方案 2（程式碼混淆）處理過後再轉成 .pyc 打包，防護效果會更好。

1. AST 代碼混淆（如 python-minifier）：完全不影響
效能變化：0% 影響（甚至微幅加快啟動速度）。

原因：混淆只是把變數、函式名稱替換成無意義的短字串（如將 get_user_data 改為 a1），並移除註解與換行。對 Python 直譯器來說，程式邏輯完全沒變，因為檔案體積變小，微秒級別的檔案載入速度甚至會變快。

2. PyArmor 動態加密：輕微影響（約 1% ~ 10%）
效能變化：一般 UI 或自動化腳本無感知，但若包含高頻率的純 Python 迴圈運算，會有較明顯的延遲。

原因：PyArmor 的防護機制是在程式執行到某個函式時，於記憶體中「即時解密」該函式，執行完畢再重新加密。

情境評估：

無感：GUI 畫面繪製、檔案讀寫、API 網路請求、資料庫存取（因為瓶頸不在 Python 代碼本身）。

有感：在 Python 內部用 for 迴圈跑數百萬次的純數學計算。

優化建議：如果運算量極大，可使用 NumPy、Pandas 等 C 語言底層套件來處理數據，PyArmor 對這類套件的調用不會造成任何效能損失。

3. 事先編譯為 .pyc 位元組碼：完全不影響
效能變化：0% 影響（僅省下極微小的啟動編譯時間）。

原因：Python 執行普通 .py 檔時，第一步本來就是先在記憶體中將其轉為 .pyc 位元組碼再執行。手動編譯為 .pyc 只是把這個動作提前完成而已。

總結建議
商業邏輯、API 或一般工具程式：直接使用 PyArmor，防護力最高且效能損失完全可忽略。

極度依賴 Python 本身 CPU 迴圈運算的程式：使用 AST 混淆（python-minifier），既能讓程式碼變得極難閱讀，又能維持 100% 的原生執行速度。

PyArmor 有可能被破解嗎? 有那些方式

有的，PyArmor 有可能被破解。 在資訊安全與逆向工程領域，只要程式需要在使用者（客戶端）的電腦上執行，就沒有 100% 完全無法破解的機制。

PyArmor 的保護強度極高，能擋掉 99% 的一般使用者與初階開發者，但對專業的逆向工程師來說，仍有以下幾種主要的破解與還原方式：

常見的 PyArmor 破解與逆向手段
1. 記憶體傾印（Memory Dumping）—— 最核心的破綻
原理：Python 解譯器（CPython）在執行程式時，最終必須將加密過的位元組碼（Bytecode）解密回記憶體的 PyCodeObject 才能交由 CPU 或直譯器執行。

破解方式：逆向者使用如 Frida、x64dbg 或 GDB 等工具，Hook 住 Python C-API 內部的函數（例如 PyEval_EvalCodeEx 或 PyMarshal_ReadObjectFromString）。在 PyArmor 解密完函式、準備執行的那一微秒，直接抓取記憶體中的解密位元組碼並傾印（Dump）出來，再重新還原成 .pyc 或 .py 檔案。

2. 動態 Hook 攔截明文（針對 JS 與 API Key）
原理：即使 Python 代碼被完好加密，當你的程式要把 JavaScript 腳本傳遞給 Electron、Selenium 或 WebSocket 時，終究必須以明文字串的形式傳送。

破解方式：逆向者不需要去破譯整個 PyArmor，而是直接用 Frida 或 API Monitor 攔截你的 Python 與 Electron / 瀏覽器之間的通訊管道（例如 Hook 住 WebSocket.send 或 execute_script）。這樣一來，傳輸中的 JavaScript 腳本就會直接以明文暴露。

3. 補丁與逆向 C 語言運行庫（Patching pyarmor_runtime.pyd）
原理：PyArmor 的動態解密與反偵錯（Anti-debugging）邏輯主要寫在 C 語言編譯成的 .pyd 擴充檔中。

破解方式：逆向專家會使用 IDA Pro 或 Ghidra 等反組譯工具去分析 pyarmor_runtime.pyd，尋找內部的解密密鑰或授權驗證點，並修改二進位檔（Patch）來繞過檢查或提取解密演算法。

4. 自動化解包腳本（Unpacker）
現狀：網路上（如 GitHub 或論壇）針對 PyArmor 7（舊版） 有不少公開的自動化拆解工具（例如 PyArmor-Unpacker）。

最新版（PyArmor 8+）：官方大幅重構了保護架構，引入了 BCC Mode（將 Python 位元組碼直接轉譯為 C 程式碼並編譯成機器碼），大幅提高了記憶體傾印與逆向的門檻，目前 PyArmor 8 的破解難度比舊版高出許多。

評估與防禦建議（針對你的自動化情境）
雖然理論上可被破解，但在商業實務上，PyArmor 的安全性已經完全足夠，因為逆向工程師花費數天甚至數週去分析你的 .exe，其成本可能已經高於直接自己重寫一隻程式。

如果你希望將核心 JavaScript 腳本與邏輯的安全性拉到最高，可以採取以下雙重防禦措施：

JavaScript 本身再做二次混淆：
寫在 Python 內部的 JS 腳本，先經過 JavaScript Obfuscator（如 javascript-obfuscator）混淆後再放入 Python 字串。即使他人從記憶體攔截到 JS 腳本，也會拿到一團極難閱讀與修改的亂碼。

使用 PyArmor 8+ 並開啟高級模式：
使用 PyArmor 8 以上版本，並盡量開啟進階保護選項（例如 --assert-call 或 BCC 模式），增加逆向者附加偵錯器（Debugger）的難度。

import base64

# 授權的電腦 UUID 白名單列表
ALLOWED_UUIDS = [
    "4C4C4544-0042-4D10-8033-B2C04F313133",
    "A1B2C3D4-E5F6-7890-1234-56789ABCDEF0"
]

def generate_whitelist_file():
    data_str = json.dumps(ALLOWED_UUIDS)
    # 簡易 Base64 處理 (亦可加入 AES 密鑰加密)
    encoded = base64.b64encode(data_str.encode('utf-8')).decode('utf-8')

    generate_whitelist_file()

import os
import sys
import json
import base64
import subprocess

def get_local_uuid():
    try:
        cmd = "wmic csproduct get uuid"
        return subprocess.check_output(cmd, shell=True).decode().split('\n')[1].strip()
    except Exception:
        return ""

def verify_whitelist():
    license_file = "whitelist.lic"
    if not os.path.exists(license_file):
        print("錯誤：找不到授權檔案 whitelist.lic！")
        sys.exit(1)
        
    try:
        with open(license_file, "r") as f:
            encoded_data = f.read()
        
        # 解密白名單
        allowed_uuids = json.loads(base64.b64decode(encoded_data).decode('utf-8'))
        local_uuid = get_local_uuid()
        
        # 比對本機 UUID 是否在白名單內
        if local_uuid not in allowed_uuids:
            print(f"錯誤：此電腦 ({local_uuid}) 未獲得執行授權！")
            sys.exit(1)
            
        print("授權驗證成功！")
    except Exception as e:
        print("授權檔案損毀或無效！")
        sys.exit(1)

# 在主流程開始前先進行驗證
if __name__ == "__main__":
    verify_whitelist()
    
    # 接下來執行原本的 Electron 注入與 Excel / SQL 邏輯...

這段的原理是什麼?

如果使用之前範例中的簡易方式（例如 Base64 編碼），User 確實可以自己修改或生成白名單。

要完全防止 User 偽造白名單，核心原理必須依賴 「非對稱加密與數位簽章（Asymmetric Cryptography & Digital Signature）」。

防偽的核心原理：公鑰與私鑰（非對稱加密）
非對稱加密會產生一對金鑰：

私鑰 (Private Key)：絕對保密，只留在開發者（你）的電腦中。只有私鑰擁有「簽署與加密」授權檔案的權限。

公鑰 (Public Key)：公開，內嵌在 .exe 程式碼中。公鑰「只能用來驗證」簽章是否正確，無法用來生成新的有效簽章。

【開發者端】 (持有私鑰)
   客戶 HWID + 你的私鑰 ──[ 簽署加密 ]──> 產生 whitelist.lic (數位簽章)
                                                  │
                                                  ▼ 發送給 User
【使用者端 .exe】 (只有公鑰)                      │
   本機 HWID + whitelist.lic + 你的公鑰 ──[ 驗證解密 ]──> 比對成功，允許執行！
為什麼 User 無法自己生成？
User 的電腦裡面只有 .exe，而 .exe 內部只有公鑰。

公鑰的數學特性是：它只能檢查這個檔案是不是由對應的私鑰簽發的，沒辦法拿公鑰倒推回私鑰。

即使 User 知道白名單的格式，也知道自己的 HWID，但因為沒有你的私鑰，他自行產生的檔案在經過 .exe 內的公鑰驗證時，都會直接被判定為「簽章無效 / 檔案遭篡改」。

兩大方案的防護原理
1. PyArmor 內建授權（方案一的背後原理）
當你使用 pyarmor gen 打包時，PyArmor 會在你的開發環境自動生成一組專屬的私鑰，並將對應的驗證公鑰寫入打包出來的 C 語言擴充庫（.pyd）中。

當你執行 pyarmor gen license --bind-disk ... 時，PyArmor 會用你的私鑰對該 HWID 進行簽署，輸出 license.lic。

執行 .exe 時，PyArmor 底層的 C 語言運行庫會調用公鑰比對本機硬體與 license.lic。

優點：完全不需要你自己寫密碼學代碼，PyArmor 已經在 C 語言層級把這套非對稱加密機制做好了。

2. 自訂 Python RSA 簽章驗證（方案二的完整實作）
如果你想自己掌控白名單檔案，可以使用 Python 的 rsa 或 cryptography 套件：

開發者端：生成一對 2048 位元的 RSA 公私鑰（private.pem 與 public.pem）。

簽發授權時：讀取 private.pem，對包含 User HWID 的 JSON 字串進行數位簽章，將「HWID 內容 + 簽章」打包成 whitelist.lic。

主程式 .exe 內部：將 public.pem 寫死在 Python 程式碼中。程式啟動時，使用 public.pem 驗證 whitelist.lic 內的簽章是否合法，再檢查目前電腦的 HWID 是否在清單內。

配合 PyArmor 打包：因為你的 Python 代碼（包含裡面的公鑰與驗證邏輯）會經過 PyArmor 混淆與動態加密，User 既拿不到私鑰，也無法修改 .exe 中的驗證邏輯。

def create_signed_whitelist(hwid_list, private_key_file, output_lic_file):
    # 1. 整理白名單資料結構
    data_dict = {
        "allowed_hwids": hwid_list,
        "note": "Authorized machines only"
    }
    # 轉為標準 JSON bytes (固定 key 的順序，確保序列化一致)
    data_bytes = json.dumps(data_dict, sort_keys=True).encode('utf-8')

    # 2. 載入開發者的私鑰
    with open(private_key_file, "rb") as f:
        privkey = rsa.PrivateKey.load_pkcs1(f.read())

    # 3. 使用私鑰對資料進行 SHA-256 數位簽章
    signature = rsa.sign(data_bytes, privkey, 'SHA-256')

    # 4. 將「明文資料」與「數位簽章」打包成 Base64 字串寫入授權檔
    license_package = {
        "data": base64.b64encode(data_bytes).decode('utf-8'),
        "signature": base64.b64encode(signature).decode('utf-8')
    }

    with open(output_lic_file, "w", encoding="utf-8") as f:
        json.dump(license_package, f, indent=4)

    print(f"白名單簽署完成！已輸出 {output_lic_file}")

if __name__ == "__main__":
    # 填入允許執行的電腦 HWID (UUID) 列表
    allowed_uuids = [
        "4C4C4544-0042-4D10-8033-B2C04F313133",
        "A1B2C3D4-E5F6-7890-1234-56789ABCDEF0"
    ]
    create_signed_whitelist(allowed_uuids, "private.pem", "whitelist.lic")

PUBLIC_KEY_PEM = """-----BEGIN RSA PUBLIC KEY-----
MIGJAoGBAM4x+3S9+7309485... (填入你公鑰檔的完整文字) ...IDAQAB
-----END RSA PUBLIC KEY-----"""

def get_local_hwid():
    """取得 Windows 本機主機板 UUID"""
    try:
        cmd = "wmic csproduct get uuid"
        output = subprocess.check_output(cmd, shell=True).decode().split('\n')
        for line in output:
            line = line.strip()
            if line and line.upper() != "UUID":
                return line
    except Exception:
        pass
    return ""

def verify_whitelist(lic_file_path):
    if not os.path.exists(lic_file_path):
        print("錯誤：找不到白名單授權檔 (whitelist.lic)")
        return False

    try:
        # 1. 讀取授權檔內容
        with open(lic_file_path, "r", encoding="utf-8") as f:
            lic_package = json.load(f)

        data_bytes = base64.b64decode(lic_package["data"])
        signature = base64.b64decode(lic_package["signature"])

        # 2. 載入公鑰並驗證簽章
        pubkey = rsa.PublicKey.load_pkcs1(PUBLIC_KEY_PEM.encode('utf-8'))
        
        # 核心防偽重點：用公鑰比對簽章，若資料曾被擅自篡改，此處會直接拋出異常
        rsa.verify(data_bytes, signature, pubkey)

        # 3. 簽章驗證成功，解開 JSON 取得白名單清單
        license_data = json.loads(data_bytes.decode('utf-8'))
        allowed_hwids = license_data.get("allowed_hwids", [])

        # 4. 比對本機 HWID 是否在許可清單內
        local_hwid = get_local_hwid()
        if not local_hwid:
            print("錯誤：無法辨識本機硬體識別碼")
            return False

        if local_hwid in allowed_hwids:
            print(f"授權成功！本機 HWID ({local_hwid}) 具備執行權限。")
            return True
        else:
            print(f"授權失敗：本機 HWID ({local_hwid}) 不在允許的白名單內！")
            return False

    except rsa.VerificationError:
        print("致命錯誤：白名單授權檔已被修改或無效，簽章驗證失敗！")
        return False
    except Exception as e:
        print(f"驗證過程發生例外錯誤: {e}")
        return False

if __name__ == "__main__":

安全機制運作說明
資料防篡改：rsa.verify() 會計算 data 的雜湊值並與用公鑰解出的 signature 比對。只要 User 修改了 whitelist.lic 中的任何一個字元，驗證步驟會立刻拋出 VerificationError。

無法自行偽造：User 若想加入自己的 HWID，必須產生新的 signature。但只有你手上的 private.pem 才能產出公鑰認可的簽章，User 僅憑 .exe 裡的公鑰是做不到的。

搭配 PyArmor 打包：將包含 PUBLIC_KEY_PEM 及驗證流程的 main.py 經由 PyArmor 加密混淆後，User 無法抽取原始碼，亦無法將 verify_whitelist() 的回傳值改成強制回傳 True。

要在 Electron 環境中保護大量 JavaScript 程式碼，最核心的架構原則是：將「注入 main.js 的程式碼」與「核心 JS 邏輯」拆開。

main.js 只需要被注入 2~3 行「引導腳本（Bootstrap Loader）」，而龐大的核心 JS 則改為二進位位元組碼 (V8 Bytecode) 或 AES 加密檔 存在磁碟中。

以下是兩種最主流且防護強度最高的解決方案：

方案一：編譯為 V8 位元組碼 (bytenode)（最推薦，安全度最高）
Node.js 與 Electron 都是基於 Google V8 引擎運作。你可以將原本的 JavaScript 文字檔編譯成 V8 Bytecode（.jsc 二進位檔）。

防禦原理
編譯後的 .jsc 檔完全不含任何原始 JS 字串與語法結構，就像 C/C++ 編譯後的機器碼一樣。使用者打開只會看到二進位亂碼，市面上也沒有成熟的 .jsc 反編譯工具。

實作步驟
開發階段：編譯 JS 為 .jsc
在開發環境安裝 bytenode，將龐大的 JS 檔案編譯成位元組码：

Bash
npm install -g bytenode
bytenode -c my_large_script.js core.jsc
(註：編譯使用的 Node/Electron 版本必須與目標 Electron 的 V8 版本一致)

Python 端的處理

Python 在啟動 Electron 前，將 core.jsc 與 bytenode.jsc（或 bytenode 套件）放入 Electron 的 App 目錄或 app.asar 中。

注入 main.js 的引導碼（只有 2 行）
你不需要把大量程式碼寫進 main.js，只需注入這段引導碼：

JavaScript

方案二：JS 混淆 + AES 動態加密（彈性高、實作簡單）
如果不想處理 V8 版本相容問題，可以採用「Python 負責保管 AES 密鑰，Electron 在記憶體中解密執行」的機制。

防禦原理
文字檔中的 JS 經過 JavaScript Obfuscator 極高強度混淆。

混淆後的內容進行 AES 加密，存成 .dat 或 .bin 檔案。

AES 密鑰硬編碼在你的 Python 程式碼中（因為 Python 已被 PyArmor 保護，使用者拿不到密鑰）。

Python 啟動 Electron 前，將解密引導腳本注入 main.js。Electron 啟動時，使用 Node.js 內建的 crypto 模組在記憶體解密 .dat 檔，並用 vm.runInThisContext() 執行。

const fs = require('fs');
const crypto = require('crypto');

function loadEncryptedModule(datFilePath, hexKey) {
    const key = Buffer.from(hexKey, 'hex');
    const fileBuffer = fs.readFileSync(datFilePath);

    // 拆解 nonce(16b), tag(16b), ciphertext

}

在完全沒有 Node.js / Electron 開發環境，且僅使用 Python 的情況下，最好的保護方式是利用 Node.js 原生就內建的 crypto（加密模組）與 vm（虛擬機記憶體執行模組）。

這意味著：你不需要安裝任何 npm 套件或 Electron 編譯工具，完全在 Python 端就能完成加密與注入。

最佳保護架構：Python AES 加密 + Node.js 原生記憶體載入
這個方案的運作原理如下：

Python 端：將你龐大的 JavaScript 文字檔，用 Python 的 AES演算法加密成一個 .dat 二進位檔（例如 payload.dat）。

注入 main.js：Python 只需要在 Electron 的 main.js 末尾追加 10 行左右的引導碼。

無痕執行：Electron 啟動時，這 10 行引導碼會調用 Electron 內建的 crypto 模組將 payload.dat 在記憶體中解密，並用 vm.runInThisContext() 直接執行，全程不會在硬碟產生任何解密後的 .js 檔。

動態密鑰（極高安全性）：解密金鑰不要寫在 main.js 裡面，而是讓 Python 在啟動 Electron 時透過環境變數（Environment Variable）傳遞。這樣一來，硬碟上的 main.js 連金鑰都沒有，別人拿著 payload.dat 也完全無法解密！

/* --- Python 注入的載入器開始 --- */
(function() {
    const fs = require('fs');
    const crypto = require('crypto');
    const vm = require('vm');
    const path = require('path');

    // 1. 從環境變數取得 Python 傳進來的 AES 金鑰
    const hexKey = process.env.INJECT_KEY;
    if (!hexKey) return;

    try {
        const key = Buffer.from(hexKey, 'hex');
        // 讀取加密的 payload.dat (路徑可根據放置位置調整)
        const datPath = path.join(__dirname, 'payload.dat');
        const fileBuffer = fs.readFileSync(datPath);

        // 2. 拆解 AES-GCM 數據 (nonce: 16b, tag: 16b)
        const nonce = fileBuffer.slice(0, 16);
        const tag = fileBuffer.slice(16, 32);
        const ciphertext = fileBuffer.slice(32);

        vm.runInThisContext(decrypted);
    } catch (e) {
        // 解密失敗或密鑰錯誤時靜默跳過
    }
})();

這個架構的安全性分析
硬碟無明文：硬碟上只有加密過的 payload.dat，別人用記事本打開只會看到亂碼。

main.js 無金鑰：注入到 main.js 的程式碼只有幾行解密邏輯，裡面完全沒有解密金鑰。別人就算打開 main.js 看到這段代碼，沒有金鑰也無法解開 payload.dat。

金鑰存在於 Python 中：解密金鑰放在 Python 程式碼中，而你的 Python 程式碼會經過 PyArmor 加密打包，逆向者無法拿到金鑰。

無痕執行：解密後的 JavaScript 直接在 V8 記憶體引擎（vm）中執行，不會生成任何 .js 暫存檔，無法從硬碟側錄。

這樣可以確保：

硬碟上只有加密檔，用記事本打開全是亂碼。

金鑰存在於受 PyArmor 保護的 Python 程式中，只有經由你的 Python 啟動 Electron 時，才會在記憶體內解密並執行。

步驟 2：寫入 main.js 的二進位引導碼 (Node.js 記憶體載入)
這段引導碼是你需要透過算好的 Offset 插入到 app.asar 中 main.js 的程式碼。它會直接調用 Electron 內建的 crypto 與 vm 模組，在記憶體中解密並執行 core.dat：

JavaScript
/* --- Injected Loader --- */
(function(){
    try {
        const fs = require('fs');
        const crypto = require('crypto');
        const vm = require('vm');
        const path = require('path');

        // 1. 從環境變數讀取 Python 傳進來的 HEX 金鑰
        const hexKey = process.env.INJECT_KEY;
        if (!hexKey) return;

        // 2. 讀取外部加密檔 core.dat (路徑可設為與 Electron.exe 同目錄或相對目錄)
        const datPath = path.join(path.dirname(process.execPath), 'core.dat');
        if (!fs.existsSync(datPath)) return;

        const buf = fs.readFileSync(datPath);
        const key = Buffer.from(hexKey, 'hex');

        // 3. 拆解 AES-GCM 數據 (nonce: 16b, tag: 16b, cipher: 剩餘部分)
        const nonce = buf.subarray(0, 16);
        const tag = buf.subarray(16, 32);
        const cipher = buf.subarray(32);

        // 4. 原生解密
        const decipher = crypto.createDecipheriv('aes-256-gcm', key, nonce);
        decipher.setAuthTag(tag);
        let decrypted = decipher.update(cipher, null, 'utf8') + decipher.final('utf8');

        // 5. 直接在 V8 記憶體中執行解密後的 JS
        vm.runInThisContext(decrypted);
    } catch(e) {}
})();
提示：如果在二進位替換時有字數限制，可將上述 JavaScript 程式碼去除換行與空格進行極小化（Minify）。

# encrypt_js.py
# 作用：將敏感的大型 JS 腳本使用 AES-256-GCM 加密，產出即使被拿到也無法讀取的 core.dat
from Crypto.Cipher import AES

# 32 位元組 (256 bits) AES 金鑰 (此金鑰需與 main.py 中的金鑰一致)
AES_KEY = b'MySecretKeyForElectronJS12345678'

def encrypt_javascript_file(input_js_path, output_dat_path):
    print(f"開始加密 {input_js_path}...")
    
    # 讀取原始明文 JS 檔案
    with open(input_js_path, 'r', encoding='utf-8') as f:
        raw_js_bytes = f.read().encode('utf-8')

    # 初始化 AES-GCM 加密器
    cipher = AES.new(AES_KEY, AES.MODE_GCM)
    ciphertext, tag = cipher.encrypt_and_digest(raw_js_bytes)

    # 將結構打包：nonce (16 bytes) + tag (16 bytes) + ciphertext (密文)
    # nonce 與 tag 用於 GCM 驗證數據完整性，防止密文被篡改
    packed_payload = cipher.nonce + tag + ciphertext

    # 寫入二進位檔案 core.dat
    with open(output_dat_path, 'wb') as f:
        f.write(packed_payload)

    print(f"【完成】已輸出加密檔案至：{output_dat_path}")

if __name__ == "__main__":

# gen_whitelist.py
# 作用：讀取許可的電腦名稱列表，使用私鑰 (private.pem) 進行數位簽章，產出白名單授權檔 whitelist.lic
import json
import base64
import rsa

def create_signed_whitelist(allowed_computer_names, private_key_path, output_lic_path):
    print("開始簽署電腦名稱白名單...")

    # 1. 將電腦名稱統一轉為大寫，避免因大小寫差異導致比對失敗
    normalized_names = [name.strip().upper() for name in allowed_computer_names]
    
    # 2. 構建白名單資料結構
    data_structure = {
        "allowed_computers": normalized_names,
        "issued_by": "Developer"
    }
    
    # 轉成固定的 JSON 字串 (sort_keys=True 確保序列化順序一致)
    json_bytes = json.dumps(data_structure, sort_keys=True).encode('utf-8')

    # 3. 讀取私鑰進行 SHA-256 數位簽章
    with open(private_key_path, "rb") as f:
        privkey = rsa.PrivateKey.load_pkcs1(f.read())
    
    signature = rsa.sign(json_bytes, privkey, 'SHA-256')

    # 4. 打包 Base64 編碼後的資料與簽章
    license_package = {
        "data": base64.b64encode(json_bytes).decode('utf-8'),
        "signature": base64.b64encode(signature).decode('utf-8')
    }

    # 寫入 whitelist.lic 授權檔
    with open(output_lic_path, "w", encoding="utf-8") as f:
        json.dump(license_package, f, indent=4)

    print(f"【完成】白名單已成功簽署並輸出至：{output_lic_path}")

def get_current_computer_name():

def verify_computer_whitelist(lic_path="whitelist.lic"):
    """使用公鑰驗證 whitelist.lic 的 RSA 簽章，並核對電腦名稱"""
    if not os.path.exists(lic_path):
        print("【授權失敗】找不到白名單授權檔：whitelist.lic")
        return False

    try:
        # 讀取授權檔
        with open(lic_path, "r", encoding="utf-8") as f:
            package = json.load(f)

        raw_data_bytes = base64.b64decode(package["data"])
        signature_bytes = base64.b64decode(package["signature"])

        # 載入內嵌公鑰並驗證數位簽章 (資料若遭篡改會直接拋出 VerificationError)
        pubkey = rsa.PublicKey.load_pkcs1(PUBLIC_KEY_PEM.encode('utf-8'))
        rsa.verify(raw_data_bytes, signature_bytes, pubkey)

        # 解開白名單資料
        data_json = json.loads(raw_data_bytes.decode('utf-8'))
        allowed_list = data_json.get("allowed_computers", [])

        # 取得本機電腦名稱並比對
        current_pc = get_current_computer_name()
        if current_pc in allowed_list:
            print(f"【驗證成功】當前電腦 ({current_pc}) 具備合法執行授權。")
            return True
        else:
            print(f"【授權失敗】當前電腦名稱 ({current_pc}) 不在許可白名單中！")
            return False

    except rsa.VerificationError:
        print("【致命錯誤】白名單授權檔簽章驗證失敗，檔案已被非授權篡改！")
        return False
    except Exception as e:
        print(f"【驗證異常】解析授權檔時發生錯誤: {e}")
        return False

        return False

        inject_bytes = code_to_inject.encode('utf-8')

        return False

def launch_electron_process(electron_exe_path):
    """將 AES 金鑰轉為 HEX 字串，寫入環境變數並啟動 Electron"""
    if not os.path.exists(electron_exe_path):
        print(f"【啟動錯誤】找不到 Electron 執行檔: {electron_exe_path}")
        return

    # 將 AES 金鑰轉換為 HEX 字串
    hex_key = AES_KEY.hex()

    # 建立環境變數副本，加入 INJECT_KEY
    env_vars = os.environ.copy()
    env_vars["INJECT_KEY"] = hex_key

    print("正在啟動 Electron 並帶入動態解密金鑰...")
    # 使用 Popen 非阻塞啟動 Electron
    subprocess.Popen([electron_exe_path], env=env_vars)
